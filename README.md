# Telegram → Google Photos: шлюз загрузки фотографий

Телеграм-бот с Mini App, который принимает фотографии в чате, спрашивает альбом
и загружает файлы в Google Photos. После успешной загрузки чат полностью
очищается — история не копится.

> **Подробная пошаговая инструкция по запуску — в файле [GUIDE.md](GUIDE.md).**

---

## Главный принцип: только запись

Бот работает строго в одну сторону — как шлюз загрузки.

* Нет ни одной команды и ни одного HTTP-endpoint, которые отдают медиа обратно
  в Telegram.
* Mini App показывает только **названия** альбомов — не содержимое.
* Из Google Photos ничего не скачивается. Используются ровно четыре вызова
  REST API: `GET /v1/albums` (список), `POST /v1/albums` (создание),
  `POST /v1/uploads` (байты файла) и `POST /v1/mediaItems:batchCreate`
  (привязка к альбому). Методы чтения медиа — `mediaItems.get`,
  `mediaItems.search`, `baseUrl` для скачивания — не вызываются нигде.
* Файлы живут во временной папке ровно столько, сколько идёт загрузка, и
  удаляются сразу после отправки (в том числе при ошибке).

## Как это работает

```
Пользователь                Бот (aiogram)            Mini App (FastAPI)        Google Photos
     |                           |                           |                       |
     |--- фото (1..N) ---------->|                           |                       |
     |                     буфер 1.5 сек                      |                       |
     |                   (media_group_id / чат)               |                       |
     |<-- «📂 Выбрать альбом» ---|                           |                       |
     |---- нажатие кнопки ------------------------------->  открытие                  |
     |                           |                      проверка initData             |
     |                           |                           |--- albums.list ------->|
     |                           |                           |<-- список альбомов ----|
     |--- выбор / новый альбом ------------------------->  POST /api/select            |
     |                           |<--- запуск загрузки ------|                        |
     |                           |--- скачивание из Telegram -|                       |
     |                           |------------------- uploads (байты) --------------->|
     |                           |------------- mediaItems:batchCreate -------------->|
     |<-- удаление сообщений ----|                           |                       |
```

1. **Приём.** Фото буферизуются 1.5 секунды (параметр `ALBUM_DEBOUNCE_SECONDS`).
   В одну сессию попадают как фото одного альбома Telegram (`media_group_id`),
   так и одиночные фото, присланные подряд в один чат.
2. **Сессия.** Для группы создаётся `session_id`, список `file_id` хранится
   **только в оперативной памяти**. На диск ничего не пишется.
3. **Выбор альбома.** Бот присылает инлайн-кнопку «📂 Выбрать альбом», которая
   открывает Mini App по адресу `{WEBAPP_URL}?session_id={session_id}`.
4. **Загрузка.** Mini App отправляет `{session_id, album_id, new_album_title}`
   на сервер и закрывается. Бэкенд скачивает фото из Telegram, выполняет
   двухшаговую загрузку в Google Photos и удаляет временные файлы.
5. **Зачистка.** При успехе удаляются все сообщения с фото, сообщение с кнопкой
   и служебные статусы. При ошибке фотографии пользователя **не трогаются**.

    ├── errors.py              ошибки в формате [HTTP <код>] <причина>: <детали>

    ├── bot/
    │   ├── middlewares.py     контроль доступа + группировка фото (debounce)

## Доступ и команды

Доступ к боту закрыт белым списком (`whitelist.db`, сверка по числовому
`telegram_user_id`). Пользователь не из списка получает ответ:

```
Вам отказано в доступе добавления фото. Для получения прав свяжитесь с @ADMIN_USERNAME
```

| Команда | Кто может | Что делает |
|---|---|---|
| `/start`, `/help` | все из белого списка | краткая инструкция |
| `/id` | все из белого списка | показать свой Telegram ID |
| `/whitelist_add <id>` | только `ADMIN_ID` | выдать доступ |
| `/whitelist_remove <id>` | только `ADMIN_ID` | отозвать доступ |
| `/whitelist_list` | только `ADMIN_ID` | список доступов |

Администратор (`ADMIN_ID`) разрешён всегда, даже если строка в базе удалена
вручную.

## Коды ошибок

Ошибки приходят пользователю в строгом HTTP-подобном формате.

| Код | Когда возникает |
|---|---|
| `[HTTP 500] Internal Server Error: <детали>` | локальный сбой: не настроен Google, ошибка файловой системы, сбой Telegram API при скачивании |
| `[HTTP 502] Bad Gateway: Не удалось связаться с серверами Google Photos.` | сеть недоступна, таймаут или ответ 5xx от Google |
| `[HTTP 503] Service Unavailable: Превышен лимит запросов Google API.` | ответ 429 или исчерпана квота |
| `[HTTP 408] Request Timeout: Время ожидания выбора альбома истекло.` | альбом не выбран за `SESSION_TIMEOUT_SECONDS` (по умолчанию 15 минут) |
| `[HTTP 400] Bad Request: Некорректный или повреждённый медиафайл.` | Google отклонил файл, файл пустой или больше лимита Telegram (20 МБ) |
| `[HTTP 401] Unauthorized` | не прошла проверка подписи `initData` (только в Mini App) |
| `[HTTP 403] Forbidden` | команда администратора от обычного пользователя либо чужая сессия |

**При любой ошибке фотографии остаются в чате** — кнопка «📂 Выбрать альбом»
продолжает работать, попытку можно повторить.

## Настройки `.env`

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_ID` | числовой Telegram ID администратора |
| `ADMIN_USERNAME` | username для текста отказа (подставляется как `@USERNAME`) |
| `WEBAPP_URL` | публичный HTTPS-адрес Mini App (туннель Cloudflare) |
| `HOST`, `PORT` | локальный адрес FastAPI (по умолчанию `127.0.0.1:8000`) |
| `ALBUM_DEBOUNCE_SECONDS` | окно группировки фото, по умолчанию `1.5` |
| `ALBUM_DEBOUNCE_MAX_WAIT` | максимальное ожидание добора группы, `15` |
| `SESSION_TIMEOUT_SECONDS` | через сколько придёт `[HTTP 408]`, по умолчанию `900` |
| `INITDATA_MAX_AGE_SECONDS` | максимальный возраст подписи Telegram, `86400` |
| `SUCCESS_NOTICE_SECONDS` | сколько секунд висит само-удаляющееся «✅ загружено» (`0` — не показывать) |
| `DB_PATH` | путь к файлу белого списка |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` | заполняются автоматически через `python auth_setup.py` |

## Учётные данные Google

Проект подключён к готовому OAuth-клиенту — создавать его заново не нужно.

| Параметр | Значение |
|---|---|
| Проект Google Cloud | `tg-bot-for-photos` |
| Тип OAuth-клиента | **Desktop app** (секция `installed` в JSON) |
| Client ID | `1087636840794-n88tl…apps.googleusercontent.com` |
| Redirect URI | `http://localhost` |
| Файл с секретом | `client_secret.json` в корне проекта |

Как это используется:

* `auth_setup.py` читает `client_secret.json`, поднимает локальный сервер на
  **случайном свободном порту** и проводит OAuth-флоу. Для клиентов типа
  *Desktop app* Google разрешает любой порт loopback, поэтому список
  **Authorized redirect URIs** в консоли заполнять не нужно — это требуется
  только для типа *Web application*.
* Результат флоу — `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и
  `GOOGLE_REFRESH_TOKEN` в `.env`. Дальше `client_secret.json` при работе бота
  не читается: `run.py` берёт значения только из `.env`.
* `refresh_token` меняется на access-токен через `https://oauth2.googleapis.com/token`;
  токен кэшируется в памяти и обновляется за минуту до истечения.

Полезные ссылки в консоли (ведут сразу в проект `tg-bot-for-photos`):

* [Photos Library API](https://console.cloud.google.com/apis/library/photoslibrary.googleapis.com?project=tg-bot-for-photos) — должен быть включён;
* [OAuth consent screen](https://console.cloud.google.com/apis/credentials/consent?project=tg-bot-for-photos) — там же список **Test users**;
* [Credentials](https://console.cloud.google.com/apis/credentials?project=tg-bot-for-photos) — повторное скачивание `client_secret.json`.

> В режиме *Testing* `refresh_token` действует 7 дней. Чтобы он стал
> бессрочным, нажмите **Publish app** на экране согласия.

## Важное ограничение Google Photos API

После **31 марта 2025 года** Google удалил из Library API scope
`photoslibrary.readonly` — запросы с ним возвращают `403 PERMISSION_DENIED`.
Поэтому проект запрашивает рабочий набор:

* `photoslibrary.appendonly` — загрузка файлов и создание альбомов;
* `photoslibrary.readonly.appcreateddata` — чтение альбомов, **созданных этим
  приложением**.

Практические следствия:

1. В списке Mini App видны **только альбомы, созданные ботом**. Альбомы,
   которые вы создавали руками в приложении Google Фото, там не появятся — это
   ограничение самого API, а не бота.
2. Загружать фото можно только в альбом, созданный ботом. Поэтому первый
   сценарий всегда — «➕ Создать новый альбом».
3. Загруженные фото видны в библиотеке Google Фото обычным образом; при
   необходимости их можно вручную перенести в любой свой альбом.
4. Если список альбомов получить не удалось, Mini App не ломается: он покажет
   текст ошибки и оставит возможность создать новый альбом.

Старый набор scopes можно запросить флагом
`python auth_setup.py --legacy-readonly` — он оставлен для проектов, которым
доступ выдали до отключения.

## Безопасность

* `.env`, `client_secret.json` и `*.db` добавлены в `.gitignore` — не коммитьте их.
* Подпись `Telegram.WebApp.initData` проверяется на каждом запросе Mini App
  (HMAC-SHA256 по токену бота) плюс проверяется возраст подписи.
* Сессия привязана к `telegram_user_id`: чужой пользователь получит `[HTTP 403]`,
  даже зная `session_id`.
* Повторная отправка той же сессии отклоняется — двойной загрузки не будет.
* Токен бота и `client_secret.json` — секреты. Если они куда-то утекли,
  перевыпустите токен через `/revoke` у @BotFather, а OAuth-клиент — в Google
  Cloud Console.
