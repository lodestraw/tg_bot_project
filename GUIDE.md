# Подробный гайд по запуску

Пошаговая инструкция «с нуля до работающего бота». Все команды — для Windows
(PowerShell). Варианты для macOS/Linux указаны отдельно.

Весь путь занимает примерно 10–15 минут: OAuth-клиент Google уже создан и
лежит в проекте, поэтому остаётся только проверить настройки в консоли и
пройти авторизацию.

## Шаг 0. Что должно быть установлено

### Python

Нужен Python 3.12 или новее. Проверьте версию:

```bash
python --version
```

Если Python не установлен или версия ниже 3.12 — скачайте его с
[python.org/downloads](https://www.python.org/downloads/) и при установке
обязательно отметьте галочку **«Add Python to PATH»**.

> Проект проверен на Python 3.12 и 3.14 — подойдёт любая из этих версий.

### cloudflared

Telegram открывает Mini App только по HTTPS, поэтому локальный сервер нужно
«вывести наружу» туннелем. Проверьте, установлен ли `cloudflared`:

```bash
cloudflared --version
```

Если команда не найдена, установите одним из способов:

```bash
winget install --id Cloudflare.cloudflared
```

Либо скачайте `cloudflared-windows-amd64.exe` со страницы
[релизов Cloudflare](https://github.com/cloudflare/cloudflared/releases),
переименуйте в `cloudflared.exe` и положите в папку из `PATH`.

*macOS:* `brew install cloudflared`

## Шаг 1. Виртуальное окружение и зависимости

Откройте терминал в папке проекта и выполните:

```bash
python -m venv .venv
```

Активируйте окружение:

```bash
.\.venv\Scripts\Activate.ps1
```

*macOS/Linux:* `source .venv/bin/activate`

> Если PowerShell ругается на политику выполнения скриптов, выполните один раз:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

Установите зависимости:

```bash
pip install -r requirements.txt
```

**В этом проекте шаг уже выполнен:** окружение `.venv` создано, зависимости
установлены. Повторять нужно только при переносе проекта на другой компьютер.

## Шаг 2. Проверка настроек Google Cloud

OAuth-клиент уже создан, скачан и лежит в корне проекта под именем
`client_secret.json`. Его параметры:

| Параметр | Значение |
|---|---|
| Проект Google Cloud | `tg-bot-for-photos` |
| Тип клиента | **Desktop app** (в JSON — секция `installed`) |
| Client ID | `1087636840794-n88tl…apps.googleusercontent.com` |
| Redirect URI | `http://localhost` |
| Client secret | в файле, в документацию не выносится |

Заново создавать ничего не нужно. Остаётся проверить три вещи — ссылки ведут
сразу в нужный проект.

### 2.1. Включён ли Photos Library API

Откройте
[страницу Photos Library API в проекте `tg-bot-for-photos`](https://console.cloud.google.com/apis/library/photoslibrary.googleapis.com?project=tg-bot-for-photos).

* Видите кнопку **Manage** — API уже включён, всё в порядке.
* Видите кнопку **Enable** — нажмите её и дождитесь включения.

Без этого шага авторизация пройдёт, но первый же запрос вернёт
`[HTTP 500] ... Google отказал в доступе` или `SERVICE_DISABLED`.

### 2.2. Ваш аккаунт в списке Test users

Откройте
[OAuth consent screen](https://console.cloud.google.com/apis/credentials/consent?project=tg-bot-for-photos).

1. Тип приложения должен быть **External**.
2. В разделе **Test users** → **Add users** добавьте тот аккаунт Google, в
   библиотеку которого бот будет складывать фото.

Если аккаунта там нет, на шаге 3 Google ответит `access_denied`.

> **Про режим Testing.** Пока приложение в статусе *Testing*, `refresh_token`
> живёт **7 дней**, после чего бот начнёт отвечать
> `[HTTP 500] ... invalid_grant` — нужно заново выполнить
> `python auth_setup.py`. Чтобы токен стал бессрочным, нажмите **Publish app**:
> для личного использования верификация Google не требуется, достаточно
> подтвердить предупреждение.

### 2.3. Клиент на месте

На странице
[Credentials](https://console.cloud.google.com/apis/credentials?project=tg-bot-for-photos)
в разделе **OAuth 2.0 Client IDs** должна быть запись с типом **Desktop**.

Если `client_secret.json` когда-нибудь потеряется — нажмите на этой записи
иконку скачивания (**Download JSON**) и положите файл в корень проекта под
именем `client_secret.json`.

### Почему хватает `redirect_uri = http://localhost`

`auth_setup.py` поднимает временный локальный сервер на **случайном свободном
порту** (`run_local_server(port=0)`). Для клиентов типа **Desktop app** Google
разрешает любой порт на loopback-адресе, поэтому в консоли ничего дописывать не
нужно. Список **Authorized redirect URIs** приходится заполнять вручную только
для типа *Web application* — у нас не тот случай.

## Шаг 3. Одноразовая авторизация Google

При активированном окружении выполните:

```bash
python auth_setup.py
```

Скрипт возьмёт `client_secret.json` проекта `tg-bot-for-photos`, поднимет
локальный сервер на случайном порту и проведёт вас через OAuth-флоу.

Что произойдёт:

1. Откроется браузер с окном входа Google.
2. Выберите аккаунт, добавленный в **Test users**.
3. Появится предупреждение «Google hasn't verified this app» — нажмите
   **Advanced → Go to … (unsafe)**. Это нормально для личного приложения,
   которое не проходило верификацию Google.
4. Подтвердите запрошенные права.
5. Во вкладке появится «Авторизация прошла успешно», а в терминале — список
   записанных переменных.

Скрипт сам допишет в `.env` три строки:

```
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REFRESH_TOKEN=...
```

Запрашиваются права:

* `photoslibrary.appendonly` — загрузка файлов и создание альбомов;
* `photoslibrary.readonly.appcreateddata` — чтение альбомов, созданных ботом.

> Почему не `photoslibrary.readonly`: Google удалил этот scope из Library API
> после 31.03.2025, запросы с ним возвращают `403 PERMISSION_DENIED`.
> Подробности и следствия — в разделе README
> «Важное ограничение Google Photos API».

## Шаг 4. HTTPS-туннель Cloudflare

**Откройте отдельное окно терминала** (оно должно оставаться открытым всё время
работы бота) и запустите:

```bash
cloudflared tunnel --url http://localhost:8000
```

В выводе найдите строку вида:

```
+--------------------------------------------------------------------------------------------+
|  Your quick Tunnel has been created! Visit it at:                                           |
|  https://optimal-submit-bet-innovation.trycloudflare.com                                    |
+--------------------------------------------------------------------------------------------+
```

Скопируйте этот адрес.

> ⚠️ **Главный источник проблем.** Быстрый туннель (`--url`) выдаёт **новый
> случайный адрес при каждом запуске**. После каждого перезапуска `cloudflared`
> нужно вписать новый адрес в `WEBAPP_URL` в `.env` и перезапустить `run.py`.
> Если адреса не совпадают, кнопка «📂 Выбрать альбом» будет открывать пустую
> страницу или ошибку.
>
> Чтобы адрес не менялся, подключите домен к Cloudflare и создайте именованный
> туннель: `cloudflared tunnel create <имя>`.

## Шаг 5. Проверка `.env`

Откройте `.env` и убедитесь, что заполнено всё:

```ini
BOT_TOKEN=8935298943:AAG...          # токен от @BotFather
ADMIN_ID=1043943081                  # ваш числовой Telegram ID
ADMIN_USERNAME=1043943081            # подставляется в текст отказа как @...
WEBAPP_URL=https://<адрес-из-шага-4> # БЕЗ слэша в конце
HOST=127.0.0.1
PORT=8000

GOOGLE_CLIENT_ID=...                 # появились после шага 3
GOOGLE_CLIENT_SECRET=...
GOOGLE_REFRESH_TOKEN=...
```

Два момента, на которые стоит посмотреть:

* **`WEBAPP_URL`** должен совпадать с адресом текущего туннеля и начинаться с
  `https://`.
* **`ADMIN_USERNAME`** сейчас равен `1043943081`, поэтому в сообщении об отказе
  будет написано «свяжитесь с @1043943081». Если нужен обычный username —
  впишите его без `@`, например `ADMIN_USERNAME=ivan_petrov`.

## Шаг 6. Запуск

В окне с активированным окружением (туннель из шага 4 продолжает работать в
соседнем окне):

```bash
python run.py
```

Признак успешного старта:

```
10:42:01 | INFO     | run | бот @your_bot запущен
10:42:01 | INFO     | run | Mini App слушает http://127.0.0.1:8000
10:42:01 | INFO     | run | публичный адрес Mini App: https://....trycloudflare.com
```

Бот и веб-сервер работают **в одном процессе** — так и задумано: сессии
загрузки хранятся в памяти и нужны обеим частям. Запускать `uvicorn` отдельно
не нужно.

Остановка — `Ctrl + C`.

Быстрая проверка, что веб-часть жива (в третьем окне терминала):

```bash
curl http://127.0.0.1:8000/healthz
```

Ожидаемый ответ: `{"ok":true,"google_configured":true}`

## Шаг 7. Первая проверка в Telegram

1. Откройте чат с ботом и отправьте `/start` — должна прийти инструкция.
2. Отправьте одну фотографию. Через ~1.5 секунды придёт сообщение
   «Получено фото: 1» с кнопкой **«📂 Выбрать альбом»**.
3. Нажмите кнопку — откроется Mini App.
4. В поле «➕ Создать новый альбом» введите название, например
   `Тест загрузки`, и нажмите **Создать**.
5. Mini App закроется. Через несколько секунд сообщения с фото и кнопкой
   исчезнут из чата, на 3 секунды появится «✅ 1 фото загружено».
6. Откройте [photos.google.com](https://photos.google.com) — фото будет в
   библиотеке и в альбоме `Тест загрузки`.

Затем проверьте группу: отправьте 3–5 фото одним альбомом. Они должны
собраться в **одну** сессию и загрузиться вместе.

## Шаг 8. Выдача доступа другим людям

1. Попросите человека написать боту — он получит отказ (это нормально).
2. Узнайте его числовой ID: пусть отправит `/id` любому боту, который это
   показывает, либо посмотрите ID в логах `run.py` — там будет строка
   `доступ запрещён: user_id=...`.
3. Выполните в чате с ботом:

```
/whitelist_add 123456789
```

4. Проверить список: `/whitelist_list`, отозвать доступ:
   `/whitelist_remove 123456789`.

## Повседневный запуск

Каждый раз нужно два окна терминала.

**Окно 1 — туннель:**

```bash
cloudflared tunnel --url http://localhost:8000
```

**Окно 2 — бот** (не забудьте обновить `WEBAPP_URL` в `.env`, если адрес
туннеля изменился):

```bash
.\.venv\Scripts\Activate.ps1
python run.py
```

Короткий чек-лист:

- [ ] туннель запущен, адрес скопирован;
- [ ] `WEBAPP_URL` в `.env` совпадает с адресом туннеля;
- [ ] `python run.py` показал «бот @... запущен»;
- [ ] `/start` в Telegram отвечает.

## Решение проблем

| Симптом | Причина и что делать |
|---|---|
| Кнопка «📂 Выбрать альбом» открывает пустую страницу или ошибку | `WEBAPP_URL` не совпадает с текущим адресом туннеля. Обновите `.env` и перезапустите `run.py` |
| В Mini App: `[HTTP 401] Unauthorized` | Страница открыта не из Telegram (в обычном браузере подписи нет) либо `BOT_TOKEN` в `.env` не тот, что у бота. Открывайте только по кнопке в чате |
| В Mini App: `[HTTP 408] Request Timeout` | Сессия истекла (по умолчанию 15 минут) или `run.py` перезапускали — сессии хранятся в памяти. Отправьте фото заново |
| `[HTTP 500] ... invalid_grant` | `refresh_token` отозван или истёк (7 дней в режиме Testing). Выполните `python auth_setup.py` заново, лучше — опубликуйте приложение в Google Cloud |
| `[HTTP 500] ... не заданы GOOGLE_CLIENT_ID ...` | Не пройден шаг 3. Запустите `python auth_setup.py` |
| `[HTTP 500] ... SERVICE_DISABLED` или `Google отказал в доступе (HTTP 403)` | В проекте `tg-bot-for-photos` не включён Photos Library API — [включите его](https://console.cloud.google.com/apis/library/photoslibrary.googleapis.com?project=tg-bot-for-photos) и перезапустите `run.py` |
| `Error 400: redirect_uri_mismatch` при авторизации | Используется OAuth-клиент типа *Web application*. Нужен тип **Desktop app** — именно такой лежит в `client_secret.json` этого проекта; проверьте, что файл не заменён на другой |
| `[HTTP 502] Bad Gateway` | Нет сети или Google временно недоступен. Фото остались в чате — нажмите кнопку ещё раз |
| `[HTTP 503] Service Unavailable` | Превышена квота Google API. Подождите и повторите; квоты видны в Cloud Console → APIs & Services → Quotas |
| `[HTTP 400] ... Некорректный или повреждённый медиафайл` | Файл пустой, не изображение или больше 20 МБ (лимит Telegram Bot API на скачивание ботом) |
| Список альбомов пуст | Ожидаемо: API отдаёт только альбомы, созданные ботом. Создайте новый альбом через «➕ Создать новый альбом» |
| `access_denied` при авторизации Google | Аккаунт не добавлен в [**Test users**](https://console.cloud.google.com/apis/credentials/consent?project=tg-bot-for-photos) на экране согласия (шаг 2.2) |
| Бот молчит на все сообщения | Проверьте, что `run.py` запущен без ошибок и что ваш ID есть в белом списке. `ADMIN_ID` разрешён всегда |
| «Вам отказано в доступе…» у вас самого | В `.env` неверный `ADMIN_ID`. Узнайте свой ID и впишите его, затем перезапустите `run.py` |
| `OSError: [WinError 10048]` при старте | Порт 8000 занят другим процессом. Освободите порт либо поменяйте `PORT` в `.env` и перезапустите туннель на новый порт |
| Фото не удаляются после загрузки | Telegram не даёт ботам удалять сообщения старше 48 часов. Для свежих сообщений ограничений нет |
